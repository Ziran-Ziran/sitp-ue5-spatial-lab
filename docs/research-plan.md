# SITP 研究计划

研究问题：在 UE5 可控仿真中，带置信度与时序的空间语义能否提高目标搜索和路径规划的可靠性？实验平台用于控制变量、获取独立真值和重复失败条件，不把仿真成绩自动推广到现实。

阶段一固定场景、代理尺寸、目标、输入许可和按场景划分，建立引擎 NavMesh/oracle 与估计几何规划对照。阶段二加入语义识别与实体关系；比较几何-only、语义、语义+时序/置信度，保持观测和路线预算一致。阶段三逐项增加低光、重复纹理、动态遮挡和深度失效，记录退化曲线与失败原因。

主指标：导航成功、碰撞、路径效率、语义目标正确率、重规划与延迟；辅助指标：跟踪覆盖、定位误差和地图质量。按预注册条件汇总全部回合，不挑最好的路线或按真值调参。

现有最小任务已实现为两类引擎标签 oracle、固定起点、两种目标选择策略与原生 Game-world 执行，见 navigation-baseline.md。它建立可重复的引擎对照条件；视觉语义模型、在线观测几何目标导航、关系建模和泛化实验仍需另行实现与验证。不得把单场景 oracle 成功率当成语义识别或跨场景能力。

深度局部网格/A* 提供不依赖引擎网格的离线几何探针，使用明确的水平与眼高先验。先用解析地面、墙体、未知区域和代理余量检查，再对全部隔离回放帧报告固定局部起终点的路径与失败。脚边未观测导致起点失败本身是感知覆盖证据；后续补充观测应另建数据，不按城市评测真值调整地面阈值或填补未知。

固定相对俯角 0°/45°/90° 的新静态观察用于检验近场覆盖缺口；三视角与水平视图保持相同基础源帧及几何参数，分别报告局部路径和危险失败。额外观察预算明确披露，不把路径可用性提升解释为同等预算的导航成功率；后续仍须验证连续查询接入段和实际碰撞反馈。

冻结深度路径转移实验已补充连续连接段/路径足迹检查，以及不经 NavMesh 的实际 CharacterMovement、碰撞和逐帧轨迹评分。全部源帧和规划失败进入分母；重置与动作反馈的引擎位姿属于显式监督。固定三米探针不能与原语义搜索回合混为同一指标；后续应在预先冻结的目标与预算下连接在线观察、重规划和失败反馈。

停止采图的在线分支已将本次实际 RGB-D、独立几何规划、直接动作和下一次观察连接起来。比较一次初始观察与一米内重观察前缀，保留所有局部任务；新增墙体的受控干预用于验收观察反馈，不能作为静态城市分数或普遍收益。额外采图、Python 进程调用和折线路长分别报告。下一步需把估计几何接到明确语义监督或视觉识别的统一目标任务，而不是把几何探针改名为语义导航。

固定红/蓝视觉标记提供最小像素类别目标：从 RGB 判颜色类别、光轴深度估计相对位置，经独立几何路线和实际动作到达，再由独立真值核验。固定任务含背向搜索、缺失、遮挡与无效出生点；完整分母与保守足迹拒绝均保留。它验证了受控颜色目标的实际链路；更一般的家具类别识别、跨场景和语义关系仍需独立数据与模型。后续几何改进应针对规划器与连续足迹合同的一致性，用独立合成最小复现验证，再比较全部冻结任务，避免按单个失败真值放宽余量。

局部监督搜索已将当前帧/时序记忆选择接到实际移动，并保存可逐帧审计的动作与反馈。RGB-D 静态位姿回放则按固定索引从全部搜索回合导出视觉输入，保留失败与空帧，位姿真值和来源映射独立存放。后续模型或估计几何应明确改用这些观测输入、重新冻结划分和预算；不能把已有引擎标签监督或离线重渲染改称视觉语义导航。
